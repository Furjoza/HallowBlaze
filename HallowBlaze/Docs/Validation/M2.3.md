# M2.3 - Atlas discovery model

## Baseline and scope

- branch: `M2/AtlasModel`;
- baseline HEAD: `319c09278aecf4bbca24b588eb689955926f71cd`;
- Unity version: `6000.3.21f1`;
- profile schema: v2;
- run schema: unchanged at v1.

M2.3 replaces boolean node and edge discovery lists with durable, monotonic knowledge owned by `ProfileState`. It does not add travel, runtime discovery emitters, map queries, autosave orchestration, or atlas presentation.

## Transition matrices

Node discovery:

| Current | Request `Unknown` | Request `Rumored` | Request `Sighted` | Request `Visited` |
| --- | --- | --- | --- | --- |
| `Unknown` | unchanged | `Rumored` | `Sighted` | `Visited` |
| `Rumored` | unchanged | unchanged | `Sighted` | `Visited` |
| `Sighted` | unchanged | unchanged | unchanged | `Visited` |
| `Visited` | unchanged | unchanged | unchanged | unchanged |

Edge discovery:

| Current | Request `Unknown` | Request `Sighted` | Request `Traversed` |
| --- | --- | --- | --- |
| `Unknown` | unchanged | `Sighted` | `Traversed` |
| `Sighted` | unchanged | unchanged | `Traversed` |
| `Traversed` | unchanged | unchanged | unchanged |

`AdvanceNodeDiscovery` and `AdvanceEdgeDiscovery` return `true` only for a durable change. `Unknown` is represented by the absence of an entry and is never persisted. First-discovery insertion order remains stable when an entry advances.

## Profile schema v2

Each known node is persisted as `{ nodeId, state }`; each known directed edge is persisted as `{ edgeId, state }`. State IDs are lowercase stable text:

- node: `rumored`, `sighted`, `visited`;
- edge: `sighted`, `traversed`.

The profile document advances from schema v1 to v2. The run document remains schema v1, and `FileSystemSaveStore` compares future versions against the current version of the document type instead of a shared constant.

### Migration mapping

| Schema v1 field | Schema v2 field | Mapping |
| --- | --- | --- |
| `discoveredNodeIds[]` | `nodeDiscoveries[]` | each stable ID becomes `{ nodeId, state: "sighted" }` |
| `discoveredEdgeIds[]` | `edgeDiscoveries[]` | each stable ID becomes `{ edgeId, state: "sighted" }` |

Legacy boolean discovery proves that an item was known, but not that a node was visited or an edge was traversed. `Sighted` is therefore the only non-destructive unambiguous migration state.

`MigrateProfileV1ToV2` parses with duplicate-property rejection, transforms in memory, validates the complete v2 document, writes and durably flushes a same-directory temporary file, and atomically replaces current while preserving the exact v1 source as `profile.backup.json`. The existing profile v0-to-v1 and run v0-to-v1 migrations retain their original target versions.

## Runtime discovery emitters

There are currently no production call sites that emit node or edge discovery. M2.3 intentionally provides only the owning profile operations and persistence contract. M2.4 will decide when sighting, traversal, and arrival events invoke them and when a real change triggers profile persistence.

## Deferred boundaries and risks

- Runtime world validation before accepting a discovery ID belongs to M2.4, where the world catalogue and profile service are joined.
- Travel selection, day advancement, checkpoints, and route history remain M2.4-M2.5.
- Atlas filtering and presentation remain M2.6.
- The schema migration is explicit; lifecycle orchestration must invoke it before loading a v1 profile in a later integration ticket.

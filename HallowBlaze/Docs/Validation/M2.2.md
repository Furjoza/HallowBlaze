- branch: `M2/MapValidation`;

- runtime loading, travel, day advancement, discovery, profile state, map UI, and scene integration: unchanged.

M2.2 adds deterministic, multi-error validation for raw macrograph data. The validation boundary sits before the fail-fast `WorldDefinition` constructor so duplicate IDs and unresolved references can be reported together instead of requiring a partially valid runtime catalogue.

## Validation boundary

```text
raw node and edge definitions
    -> WorldGraphValidationInput snapshot
    -> WorldGraphValidator.Validate(input, expectedGoalDay?)
    -> read-only WorldGraphValidationResult
```

`WorldGraphValidationInput` defensively copies caller-owned collections while preserving their values and order. Duplicate IDs and unresolved edge endpoints are accepted at this boundary as data to diagnose. Null collections or null definition elements remain programmer-contract violations and fail immediately.

`WorldGraphValidator` excludes ambiguous IDs and unresolved edges from the usable directed graph. It resolves a unique start and goal, computes shortest directed distances with breadth-first traversal, and reports every independent problem whose prerequisites are known. Diagnostics are sorted by code, then ordinal subject, then reason, making output independent of input collection order.

The overload accepting `WorldDefinition` uses the same validation path through `WorldGraphValidationInput.FromWorldDefinition`.

## Diagnostic contract

| Rule | Focused fixture | Code | Subject | Reason |
| --- | --- | --- | --- | --- |
| duplicate node ID | two `branch` nodes | `DuplicateNodeId` | `branch` | `Node ID 'branch' is declared 2 times and is ambiguous.` |
| duplicate edge ID | two `road.start-goal` edges | `DuplicateEdgeId` | `road.start-goal` | `Edge ID 'road.start-goal' is declared 2 times and is ambiguous.` |
| missing start field | null `startNodeId` | `MissingStartNodeId` | `startNodeId` | `Required field 'startNodeId' does not contain a node ID.` |
| unresolved start | `missing.start` is undeclared | `UnresolvedStartNodeId` | `missing.start` | `Required startNodeId 'missing.start' does not resolve to a declared node.` |
| missing goal field | empty `goalNodeId` | `MissingGoalNodeId` | `goalNodeId` | `Required field 'goalNodeId' does not contain a node ID.` |
| unresolved goal | `missing.goal` is undeclared | `UnresolvedGoalNodeId` | `missing.goal` | `Required goalNodeId 'missing.goal' does not resolve to a declared node.` |
| missing edge source | `road.broken-source` starts at `missing.source` | `MissingEdgeSource` | `road.broken-source` | `Edge 'road.broken-source' source 'missing.source' does not resolve to a declared node.` |
| missing edge destination | `road.broken-destination` ends at `missing.destination` | `MissingEdgeDestination` | `road.broken-destination` | `Edge 'road.broken-destination' destination 'missing.destination' does not resolve to a declared node.` |
| unreachable node | disconnected `orphan` self-loop | `UnreachableNode` | `orphan` | `Node 'orphan' is not reachable from the declared start.` |
| non-goal dead end | reachable `dead-end` without an outgoing edge | `UnexpectedDeadEnd` | `dead-end` | `Node 'dead-end' has no usable outgoing edge and is not the explicit goal.` |
| distance layer mismatch | goal declares layer 2 but has a direct edge | `DistanceLayerMismatch` | `goal` | `Node 'goal' declares distance layer 2, shortest distance is 1.` |
| expected goal day mismatch | direct goal edge validated against day 2 | `GoalDayMismatch` | `goal` | `Goal 'goal' is reached on day 1, expected day 2.` |

## Cascade and distance semantics

- Duplicate node and edge groups produce one diagnostic per ambiguous stable ID.
- Ambiguous edges do not participate in the known traversal. A separate potential traversal includes otherwise resolvable ambiguous edges and suppresses a dependent reachability, layer, or goal-day conclusion only when it could make an unreachable node reachable or produce a shorter route than the known graph.
- Endpoint diagnostics shared by repeated declarations of one duplicate edge ID are emitted once, while distinct missing source and destination failures remain independently visible.
- An edge with an unresolved endpoint reports that endpoint and is excluded. It does not suppress independent conclusions established by other usable edges.
- Missing or ambiguous start suppresses start-dependent reachability and distance checks. Missing or ambiguous goal suppresses goal-dependent dead-end and expected-day checks.
- A malformed fixture containing both duplicate node data and a broken destination returns both independent diagnostics in one call without throwing.
- The goal day is optional. When supplied, it is compared with the shortest directed distance, not declaration order or the first enumerated route.

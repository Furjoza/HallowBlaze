# M2.4 - World map service and discovery events

## Baseline and scope

- branch: `M2/WorldMapService`;
- baseline HEAD: `c053ec45b1b585ab238a89d128ea63bdc4c55b5f`;
- Unity version: `6000.3.21f1`;
- profile schema: unchanged at v2;
- run schema: unchanged at v1.

M2.4 adds a Unity-independent `WorldMapService` that joins one immutable
`WorldDefinition` to `GameSession.Profile`, the active run position, and
`ISaveStore`. It owns knowledge-filtered map queries, legal-exit queries, and
save-backed discovery operations. It does not choose a route, move the run,
advance the day, append route history, save a run checkpoint, or render UI.

## Service boundary

```text
WorldDefinition + GameSession + ISaveStore
                  |
                  v
          WorldMapService
            |          |
            |          +-> discovery command -> ProfileState -> SaveProfile
            |
            +-> filtered atlas snapshot / current legal exits
```

The constructor rejects null dependencies, profile/world identity or version
mismatches, profile discovery IDs absent from the catalogue, and catalogue
edges with unresolved endpoints. Active-run position is validated at each query
or command because a `GameSession` may start, replace, or abandon runs after the
service is constructed.

## Knowledge-filtered queries

Unknown nodes and edges are omitted from `WorldMapSnapshot`. Known edges are
included only when both endpoint nodes are also known, so an edge cannot reveal
otherwise unknown topology.

Example node projections:

| Knowledge | `NodeId` | Atlas coordinates and layer | Place kind | Biome family |
| --- | --- | --- | --- | --- |
| `Unknown` | omitted | omitted | omitted | omitted |
| `Rumored` | correlation ID | `null` | `null` | `null` |
| `Sighted` | correlation ID | present | `null` | `null` |
| `Visited` | correlation ID | present | present | present |

Example legal-exit response at `forest.start`:

```text
road.start-east-creek | northeast | clue.running-water
road.start-west-trail | northwest | clue.dense-trees
```

Legal exits come only from directed catalogue edges whose `FromNodeId` equals
the active run's current node. Each option exposes its stable `EdgeId`, world
direction, and clue key, but not the destination identity. Query collections are
detached read-only snapshots in stable catalogue order. Querying does not mutate
profile knowledge and does not save.

## Discovery and autosave

| Operation | Durable transitions | Autosave and event behavior |
| --- | --- | --- |
| `EnterCurrentNode` | current node to `Visited` | one `SaveProfile`, then one `EnteredNode` event |
| `ObserveCurrentExits` | every outgoing edge and destination to `Sighted` | all changes in one `SaveProfile`, then one `ObservedExits` event |
| `CompleteTraversal(edgeId)` | one legal outgoing edge to `Traversed` | one `SaveProfile`, then one `TraversedEdge` event |

Events are published only after a successful profile save. A successful repeat
returns `NoChange` and performs no save or event. If `SaveProfile` fails after
the in-memory monotonic transitions, the service retains the aggregate event as
pending. Only the identical operation may retry it; a successful retry saves and
publishes exactly once. Other discovery commands are rejected while that retry
is pending.

No active run, an unknown current node or edge, and a non-outgoing edge produce
controlled rejection without profile mutation, save, or event. Discovery
operations never change `WorldNodeId`, `CurrentDay`, or `Route`, and they never
call `SaveRun`.

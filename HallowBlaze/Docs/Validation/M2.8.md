# M2.8 - Atlas Persistence Across Runs - Validation Report

## Overview
This document validates M2.8: "Proof of atlas persistence across runs" by demonstrating that discoveries made during one game run persist into subsequent runs through the ProfileState system.

## Test Implementation

### Test File: `Assets/Tests/PlayMode/M2.8AtlasPersistenceTests.cs`

The test implements an integration test that:
1. Creates a 5-day world graph using `prototype-world.json`
2. Runs two consecutive game sessions
3. Validates that discoveries from the first run persist into the second run

### Key Test Method: `AtlasPersistenceAcrossTwoRuns()`

The Unity integration test runs two sessions against an isolated temporary save
root. It saves discoveries after the first run, destroys the first manager, and
creates a fresh manager whose `EnsurePersistence()` loads a new `ProfileState`
from `profile.json`. The second atlas then verifies the persisted node and edge
states.

## Validation Evidence

### 1. World Graph Fixture
- **File**: `Assets/GameData/World/prototype-world.json`
- **Structure**: 5-day world graph with nodes at distanceLayer 0-5
- **Nodes**: 16 nodes including forest, road, village, and cave locations
- **Edges**: 15 connections forming a coherent world map

### 2. Discovery State Management
The test validates the following discovery states:
- **NodeDiscoveryState**: Tracks node visibility (Unknown, Sighted, Visited)
- **EdgeDiscoveryState**: Tracks edge visibility (Unknown, Sighted, Visited)
- **Persistence**: Discoveries are stored in `ProfileState` and loaded into a new session

### 3. Two-Run Sequence
The test demonstrates:
1. **First Run**: Player discovers new nodes and edges through exploration
2. **Second Run**: ProfileState loads discoveries from disk, making them available in the new run
3. **Persistence Proof**: Assertions verify that discoveries from run 1 are visible in run 2

## Known Issues and Limitations

### 1. Test Assumptions
- The atlas prefab supplies the world-definition `TextAsset` reference because
   `prototype-world.json` is outside a `Resources` folder.
- The test uses a unique temporary persistence root and deletes it in teardown.

### 2. Implementation Notes
- Test uses undiscovered nodes/edges to avoid conflicts with `BeginRouteChoice()`
- `forest.west-grove` and `road.old-road-west-grove` are chosen as they are not discovered by `BeginRouteChoice()`
- Test explicitly closes atlas between runs to simulate real gameplay

## 1. Zakres wyniku

M1.5 wprowadza granicę trwałości niezależną od runtime'owych klas domenowych. `ProfileStateDto` i `RunStateDto` definiują logiczną schema v1, mappery wykonują jawne przejście do i z domeny, a `PersistenceJsonSerializer` serializuje osobne dokumenty profilu i runu przez dostępny w projekcie Json.NET.

Assembly `HallowBlaze.Core.Persistence` ma `noEngineReferences: true`. Referencjonuje wyłącznie `HallowBlaze.Core.State` i `Unity.Newtonsoft.Json`; DTO nie przechowują `GameObject`, `MonoBehaviour`, `Transform`, assetów, `InstanceID` ani innych referencji `UnityEngine.Object`.

Ticket nie implementuje produkcyjnego filesystem store, ścieżki `persistentDataPath`, atomowej zamiany, backupu, recovery, chmury, szyfrowania, `Continue`, migracji prototypowych `PlayerPrefs` ani pełnego snapshotu `BoardState`.

## 2. Schema v1

Profil i run są osobnymi dokumentami. Każdy dokument posiada wymagane `schemaVersion` równe `1`. Serializer odczytuje wersję przed mapowaniem pozostałych pól, dlatego dokument v2 ani dokument bez wersji nie może zostać zinterpretowany jako v1.

Status runu jest trwałym tekstowym ID: `active`, `dead` albo `won`. Pusty slot narzędzia ma `toolId: ""` i `remainingUses: 0`; `null` oznacza brak wymaganego pola i jest odrzucane.

### Zredagowany profil

```json
{
  "schemaVersion": 1,
  "profileId": "<redacted-profile-id>",
  "worldDefinitionId": "world.default",
  "worldDefinitionVersion": 1,
  "discoveredNodeIds": ["<redacted-node-id>"],
  "discoveredEdgeIds": ["<redacted-edge-id>"],
  "discoveredFactIds": ["<redacted-fact-id>"],
  "persistentNoteIds": ["<redacted-note-id>"],
  "runSummaries": [
    {
      "runId": "<redacted-run-id>",
      "daysSurvived": 4,
      "status": "dead"
    }
  ]
}
```

### Zredagowany run

```json
{
  "schemaVersion": 1,
  "runId": "<redacted-run-id>",
  "runSeed": 0,
  "currentDay": 2,
  "worldNodeId": "<redacted-node-id>",
  "health": 80,
  "food": 65,
  "status": "active",
  "toolSlots": [
    { "toolId": "<redacted-tool-id>", "remainingUses": 2 },
    { "toolId": "", "remainingUses": 0 }
  ],
  "route": ["<redacted-route-node-id>"]
}
```

Serializer ani mappery nie logują dokumentów, DTO ani pełnych danych profilu. Kontrolowane wyjątki zawierają kategorię i ścieżkę pola, ale ich komunikaty nie interpolują odrzuconych wartości.

## 3. Mapowanie profilu

| Pole domeny | Pole DTO v1 | Reguła |
| --- | --- | --- |
| `ProfileState.ProfileId` | `profileId` | wymagane stabilne tekstowe ID |
| `WorldDefinitionId` | `worldDefinitionId` | wymagane stabilne tekstowe ID |
| `WorldDefinitionVersion` | `worldDefinitionVersion` | liczba dodatnia |
| `DiscoveredNodeIds` | `discoveredNodeIds[]` | unikalne stabilne ID, zachowana kolejność |
| `DiscoveredEdgeIds` | `discoveredEdgeIds[]` | unikalne stabilne ID, zachowana kolejność |
| `DiscoveredFactIds` | `discoveredFactIds[]` | unikalne stabilne ID, zachowana kolejność |
| `PersistentNoteIds` | `persistentNoteIds[]` | unikalne stabilne ID, zachowana kolejność |
| `RunSummaries[].RunId` | `runSummaries[].runId` | unikalne stabilne ID runu |
| `RunSummaries[].DaysSurvived` | `runSummaries[].daysSurvived` | wartość nieujemna; suma nie przekracza `int.MaxValue` |
| `RunSummaries[].Status` | `runSummaries[].status` | wyłącznie `dead` albo `won` |
| agregaty profilu | brak osobnych pól | odtwarzane przez `RecordRunSummary`, bez duplikowania źródła prawdy |

Mapper najpierw waliduje wszystkie kolekcje i summaries, a dopiero potem tworzy `ProfileState` i wykonuje monotoniczne operacje domenowe. Wadliwy DTO nie pozostawia częściowo odtworzonego profilu.

## 4. Mapowanie runu

| Pole domeny | Pole DTO v1 | Reguła |
| --- | --- | --- |
| `RunId` | `runId` | wymagane stabilne tekstowe ID |
| `RunSeed` | `runSeed` | pełny zakres `int` |
| `CurrentDay` | `currentDay` | wartość nieujemna |
| `WorldNodeId` | `worldNodeId` | wymagane stabilne tekstowe ID |
| `Health` | `health` | wartość nieujemna |
| `Food` | `food` | wartość nieujemna |
| `Status` | `status` | `active`, `dead` albo `won` |
| `ToolSlots[0..1].ToolId` | `toolSlots[0..1].toolId` | dokładnie dwa sloty; stabilne ID albo pusty string |
| `ToolSlots[0..1].RemainingUses` | `toolSlots[0..1].remainingUses` | wartość nieujemna; pusty slot wymaga zera |
| `Route` | `route[]` | stabilne ID; kolejność i powtórzenia są zachowane |

Run jest rekonstruowany jako aktywny z konfiguracji zapisanych wartości. Dopiero po odtworzeniu trasy i narzędzi mapper aplikuje terminalne `MarkDead` albo `MarkWon`, dzięki czemu nie omija inwariantu blokującego mutacje zakończonego runu.

## 5. Katalog błędów walidacji

Wszystkie błędy danych używają `PersistenceDataException` z typowanym `PersistenceDataError` i `FieldPath`.

| Błąd | Przykładowa przyczyna | Zachowanie |
| --- | --- | --- |
| `EmptyDocument` | `null`, pusty tekst lub whitespace | dokument odrzucony przed parserem |
| `InvalidJson` | uszkodzona składnia, wiele korzeni lub duplikat właściwości | dokument odrzucony bez wyboru jednej z konkurencyjnych wartości |
| `MissingField` | brak `schemaVersion`, wymaganej kolekcji, summary, slotu lub `toolId: null` | kontrolowany błąd bez rekonstrukcji domeny |
| `UnsupportedSchemaVersion` | `schemaVersion` inne niż `1` | dokument nie jest interpretowany jako v1 |
| `InvalidStableId` | puste ID albo whitespace na jego brzegu | pole odrzucone ze ścieżką elementu |
| `DuplicateId` | powtórzone odkrycie lub `runId` summary | kolekcja odrzucona przed mutacją domeny |
| `InvalidValue` | ujemny zasób, zły status, liczba slotów inna niż dwa lub overflow sumy dni | DTO odrzucone przed utworzeniem obserwowalnego stanu |

Nieznane właściwości JSON są odrzucane przez `MissingMemberHandling.Error`. Błędy Json.NET są normalizowane do kontrolowanego błędu persistence i nie ujawniają treści dokumentu w komunikacie.

## 6. Round-trip i izolacja danych

Testy potwierdzają round-trip:

- pełnego profilu z kolekcjami w kolejności wstawienia, terminalnym summary i wartościami maksymalnymi;
- minimalnego pustego profilu;
- aktywnego runu z pełnym zakresem seeda, wartościami maksymalnymi, dwoma narzędziami i trasą;
- minimalnego runu z zerowymi zasobami i pustymi slotami;
- runów terminalnych `Dead` oraz `Won`, które po odtworzeniu nadal odrzucają mutacje.

Mappery kopiują kolekcje z domeny do tablic DTO, a odtwarzanie kopiuje wartości DTO przez operacje domenowe. DTO pozostają prostymi, modyfikowalnymi obiektami granicznymi i nie stają się właścicielem kolekcji domeny.

## 8. Review

Pierwszy niezależny `qwen-reviewer` wydał `Fail` z jednym findingiem `MEDIUM`: bezpośredni `RunStateMapper.FromDto` traktował `ToolSlotDto.ToolId == null` jak legalny pusty slot, mimo że pole jest wymagane.

Po poprawce `null` daje `MissingField` na `toolSlots[index].toolId`, natomiast pusty string z `remainingUses == 0` pozostaje reprezentacją pustego slotu. Dodano test regresji `NullToolIdReturnsMissingFieldWhileEmptyToolIdRemainsAnEmptySlot`; filtrowany suite wzrósł z 17 do 18 przypadków.

Ponowny niezależny review zakończył się werdyktem **PASS**. Reviewer potwierdził zamknięcie findingu i nie znalazł innych materialnych problemów. Jako niematerialną lukę wskazał brak osobnego testu wejścia JSON z `"toolId": null`; bezpośredni test mappera i kontrakt `Required.Always` pokrywają obecne zachowanie.

# M1.8 — kontrakt własności i trwałości

## Zakres

Macierz integracyjna używa prawdziwego `FileSystemSaveStore` w unikalnych katalogach pod `Path.GetTempPath()`. Każdy fixture jawnie tworzy profil i run w schemacie `v1` przez publiczne modele domenowe. Testy nie odczytują ani nie zapisują katalogu prawdziwego profilu gracza.

## Niepokryte zachowania

- Ręczny smoke na kopii testowego profilu: `Failed — blockers filed`. `Continue` zachował dzień i zasoby, ale wygenerował nowy układ planszy oraz pozycję startową, umożliwiając reroll bez kosztu. Naprawę opisuje `M1.10`.
- Podstawowy ruch nie pozostał stabilnie kafelkowy, a kontakt z zombie nie wywoływał niezawodnie oczekiwanej interakcji. Regresja blokuje wiarygodne domknięcie smoke'a; naprawę opisuje `M1.9`.
- Widok porażki oferował wyłącznie `Restart`, który natychmiast rozpoczyna kolejny run. Brak ścieżki powrotu do menu uniemożliwił ręczne sprawdzenie niedostępności `Continue` po terminalnym wyniku; uzupełnienie opisuje `M1.11`.
- Automatyczna macierz własności i persistence jest zielona, ale cały ticket M1.8 pozostaje otwarty do naprawienia blockerów i powtórzenia ręcznego smoke'a.
